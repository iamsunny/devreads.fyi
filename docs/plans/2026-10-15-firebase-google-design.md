# Firebase Google-only authentication

Approved: replace Better Auth with standard Firebase Authentication, supporting Google only. Keep static Astro, Cloudflare hosting, D1 Favorites, local guest hearts and acknowledged imports. Do not enable Identity Platform or add Firestore.

- [x] Replace Better Auth with Firebase ID-token verification in the Worker and Google-only Firebase client sign-in.
- [x] Add a Firebase project/UID-to-application-user mapping without implicit email linking, and short-lived deletion markers. Preserve existing databases and historical migrations.
- [x] Use Firebase SDK-managed browser persistence and bearer ID tokens for API requests. Do not manually persist tokens or retain Google access/refresh tokens in D1. This replaces the old 30-day Better Auth cookie/session design; explain the persistence change in privacy/setup documentation.
- [x] Verify RS256 signatures against Google's rotating public keys, exact project issuer/audience, expiry/issued/authentication times, Google provider and verified email. Check the Firebase account's current status and token revocation time, with a bounded 60-second cache; reject deleted application identities immediately.
- [x] Keep exact-origin/preview controls and native rate limits. Coordinate Firebase account deletion with D1 cleanup, require authentication within five minutes, and provide Google reauthentication. Old linking/provider-token APIs stay closed.
- [x] Replace multi-provider UI, configuration, local development docs and tests. Keep sign-in disabled until real Firebase web config and Google callbacks are verified.
- [ ] Test signed-token verification, account status/revocation, ownership, import/retry, deletion, SDK failures, browser behavior and existing site regressions; push/deploy the tested inactive integration and record external activation prerequisites.

Firebase SDK persistence may use IndexedDB/localStorage under the SDK's own keys. ID tokens are transmitted only over HTTPS in Authorization headers; never logged, placed in URLs, or stored in application Favorites data. Public Firebase web configuration is not an admin credential. No service-account key is required: account lookup/deletion use the authenticated user's ID token through Firebase's REST API. Tests use disposable D1 storage, locally signed JWTs, mocked Google/Firebase network responses and a test-only browser provider adapter; no public test-login endpoint or unsigned-token acceptance is deployed.

Remote activation needs production and staging Firebase project web configurations, Google enabled as the sole provider, authorized domains, and successful real popup/reauthentication/callback checks. Existing D1 auth tables remain for rollback; active application auth no longer reads Better Auth sessions.

Implementation verification: strict Worker types, six unit tests, seven signed-token workerd/D1 groups and twelve Chrome groups passed. The browser checks cover Google-only UI, popup cancellation/retry, safe return, import/second device, owner switching, write rollback, partial import retry, logout, reauthentication control, deletion, both themes at 320-1,440px, actual Firebase SDK initialization and unavailable-SDK guest saving. The API Worker bundle is approximately 57KiB (16KiB gzip); the browser Firebase bundle is approximately 140KiB. Firebase 13.0.0 and jose 6.2.12 are pinned; the transitive gRPC advisory was fixed and npm audit reports zero vulnerabilities. Migration 0002 is applied remotely to production and staging; production contained zero users/Favorites before migration. Real Firebase project configuration and Google callbacks remain outstanding.
